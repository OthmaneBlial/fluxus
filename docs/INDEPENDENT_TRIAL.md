# Brief for an independent first use

Use this brief when asking a JavaScript or TypeScript developer to try Fluxus. Send only the public entry points and the task below before the trial. Do not explain the API, the expected clicks or the intended solution until the participant has finished or stopped.

## Participant task

Starting from a clean folder, try the published `@othmaneblial/fluxus@0.1.1` package and the public task workbench. Decide whether you can understand and reproduce the small task workspace: add a task, complete it, filter open tasks, pause the event observer, and reset the sample. Stop after 15 minutes or when you can explain the action, reducer, state and subscriber path in your own words.

Public entry points:

- npm: `npm install @othmaneblial/fluxus@0.1.1`
- workbench: <https://othmaneblial.github.io/fluxus/>
- guide: [`docs/GETTING_STARTED.md`](GETTING_STARTED.md)

## Coordinator protocol

1. Record the package version and date before the participant starts.
2. Give the participant the task and links, then do not coach the first attempt.
3. Record the first blocker in the participant's own words, without names or contact details.
4. After the attempt, answer questions and verify the reported result against the public demo or a clean consumer.
5. Add one anonymized row to [`USER_FEEDBACK.md`](USER_FEEDBACK.md), and open or reference an issue only when a concrete fix is needed.

Do not collect credentials, private project code, personal data or invented success quotes. Three completed rows are required before phase 6.1 can be marked complete.
